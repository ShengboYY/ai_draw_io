# 临时与长期证据统一索引到 Pinecone

所有上传资料，包括匿名和登录用户的临时资料，都使用同一套摄取与 Pinecone 检索链路。MySQL 继续作为所有权、作用域、生命周期和访问权限的事实源，原文件与完整证据保留在现有 AWS 区域。该方案通过放弃单独的本地精确检索路径来减少重复实现，同时接受额外的 Pinecone 写入、容量、删除和供应商留存控制。

## 结果

- 临时记录必须通过服务端选择的 namespace 和元数据过滤隔离，客户端不能指定租户过滤条件。
- 所有临时资料到期时先由 MySQL 拒绝新的检索和读取租约；已有租约结束后立即删除 Pinecone 投影，避免失效资料继续占用向量容量或被召回。
- 匿名临时资料不进入回收站；已有租约结束或超时后，立即永久删除原文件和解析派生物。登录用户临时资料进入回收站保留 30 天；恢复后仍属于原图表会话的临时作用域，从恢复时刻重新获得 24 小时有效期，并复用派生物重建 Pinecone 投影，不重复执行 OCR。
- 每个检索候选在回源前都必须重新经过 MySQL 鉴权；Pinecone 中尚未完成删除的记录不能单独构成可访问证据。
- 匿名上传必须使用专用限额和熔断保护 Pinecone 存储及月度 Write Units。
