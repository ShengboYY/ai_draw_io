# Material RAG baseline — 2026-07-20

## Decision summary

The project can retrieve small, clean, text-heavy PDFs well, but the current dense path is not yet a
safe default for long or layout-heavy PDFs. The controlled corpus reached Recall@10 `1.00`; the
pinned Scrum Guide and NIST AI RMF corpus reached only `0.70`. The main measured failure is not
Pinecone capacity: NIST's 48 PDF pages became 2,783 searchable chunks, of which 2,771 are content
chunks with a median of only 85 tokens. That fragmentation dilutes page context before ranking.

Do not solve this first by only increasing `topK`. Recall rose from `0.70` at 10 to only `0.80` at 40,
while both trustworthy-AI-characteristic queries remained absent. Fix paragraph/evidence grouping,
then measure hybrid retrieval and reranking on the same locked cases.

## What was tested

- The real project path: `PdfBoxDocumentParser -> CanonicalPageAssembler -> EvidenceUnitBuilder ->
  RetrievalChunkBuilder -> multilingual-e5-large -> Pinecone`.
- The exact production tokenizer exported from the current Worker image and verified by its pinned
  SHA-256.
- Two generated, visually reviewed eight-page digital PDFs (V1 and V2), one three-page image-only
  scanned PDF, two deterministic diagram/table images, and one generated photographed-whiteboard
  challenge image.
- Ten manually labelled questions over pinned authoritative PDFs: six over the Scrum Guide 2020 and
  four over NIST AI RMF 1.0. Each fact has a physical PDF page label; exact phrase matching is used
  first and the labelled page is the fallback relevance boundary when PDFBox splits a phrase across
  evidence units.
- Tesseract `4.1.1` with `eng+chi_sim` against the three controlled scan pages.

The source manifest pins the official PDFs by SHA-256. NASA's handbook is pinned and 4 cases are
defined, but it was not included in this baseline run.

Wilson 95% intervals are wide because this is a diagnostic cohort, not the locked release set:

- Controlled R@10: `1.0000` (`0.8794–1.0000`), n=28.
- Open R@10: `0.7000` (`0.3968–0.8922`), n=10.
- Open R@40: `0.8000` (`0.4902–0.9433`), n=10.
- Open English R@10: `0.8000` (`0.3755–0.9638`), n=5.
- Open Chinese-query R@10: `0.6000` (`0.2307–0.8824`), n=5.

Open weak cases:

- `open-nist-001-en`: trustworthy AI characteristics, not in top 40.
- `open-nist-001-zh`: same English evidence requested in Chinese, not in top 40.
- `open-scrum-003-zh`: Sprint Retrospective query, rank 12.

The controlled table slice achieved R@10 `1.00` (n=6), but this small synthetic table result must not
be generalized to arbitrary tables.

### Chunk projection

| Source | pages | searchable chunks | token p50 | token p95 | max | exact phrase mapped | page relevance mapped |
|---|---:|---:|---:|---:|---:|---:|---:|
| Scrum Guide | 14 | 126 | 104 | 336 | 375 | 6/6 | 6/6 |
| NIST AI RMF | 48 | 2,783 | 85 | 133 | 377 | 0/4 | 4/4 |

NIST's type distribution is `CONTENT=2771`, `SECTION_BRIDGE=11`, `DOCUMENT_PROFILE=1`. Its exact
phrases are present on the labelled page but cross evidence/chunk boundaries. This is direct evidence
that native block/evidence grouping should be investigated before changing the vector database.

The Chinese OCR changed semantic labels such as `安全阈值`/`阈值`, although document codes and values
survived. Anchor recall is therefore `1.00` (`0.5655–1.0000` Wilson 95%, n=5), but semantic retrieval
can still degrade when a query names the damaged label. This run measures OCR extraction, not
post-OCR Pinecone recall.

## Product-specific diagnosis

1. **P0 — consolidate native PDF blocks before projection.** Add a regression fixture based on the
   NIST page structure, merge spatially contiguous lines into paragraphs while preserving source
   regions, and gate on chunks/page plus exact/page-anchor mappability. Re-run this baseline before
   any ranking work.
2. **P0 — add parent/page context to candidate scoring.** Leaf vectors currently carry short text;
   test embedding the existing parent context or retrieving leaf then ranking a parent/page window.
   Keep citations at Evidence/page boundaries.
3. **P1 — evaluate the online hybrid path.** This baseline isolates dense retrieval. Run lexical-only,
   dense-only and current weighted RRF (`lexical=1.2`, `dense=1.0`, `k=60`) as paired experiments.
   Exact identifiers and NIST terminology are expected to benefit from lexical candidates, but this
   remains unmeasured.
4. **P1 — rerank after candidate generation.** Candidate generation currently has no semantic
   reranker. Compare a multilingual cross-encoder or LLM reranker over top 30/40 and report paired
   nDCG@10, MRR@10, latency and cost. Do this after fragmentation is reduced, otherwise the reranker
   receives incomplete evidence.
5. **P1 — complete scanned-PDF retrieval.** Preserve OCR alternatives and confidence; add queries for
   both exact values and damaged Chinese labels. Measure OCR anchor mappability, dense/lexical recall
   and citation page accuracy, not CER alone.
6. **P1 — implement verified visual evidence before scoring visual recall.** The current online route
   deliberately returns `VISUAL_VERIFICATION_REQUIRED`; therefore flow arrows, tables rendered only
   as images and the whiteboard fixture cannot yet complete the normal evidence bundle path.
7. **P2 — test downstream limits only after candidate recall is healthy.** The current sequence is
   candidate top 40, fused 30, hydrated 16 and bundled 8, with at most three items per material.
   Instrument gold survival at each boundary before tuning these values.

## Experiment validity and limits

- 52 controlled cases and 14 open cases are defined (66 total), but this report executes 28
  text/table controlled cases and 10 Scrum/NIST cases. It is not the planned 180-case release suite.
- Confidence intervals are reported, but the open cohort is deliberately small and diagnostic.
- Dense retrieval is measured directly. Hybrid, authorization, hydration, final bundle, answer
  support, citation precision, version pinning, owner isolation, no-answer and Pinecone-degradation
  experiments remain to be run through the online orchestrator.
- The photographed whiteboard was generated as a challenge fixture and manually inspected; its
  visual recall has not been scored because the verified visual analysis path is not implemented.
- Live tests require a namespace containing `test` or `dev`, use a unique run prefix, batch Pinecone
  writes/deletes, and verify vector deletion. They skip in ordinary CI unless credentials and source
  paths are explicitly supplied.

## Acceptance targets for the next baseline

- Gold relevance mappability: `100%` before retrieval.
- Digital PDF candidate R@10: `>=0.90`; R@40: `>=0.95` overall and for EN/ZH slices with n>=20 each.
- Exact identifier lexical R@5: `>=0.95`.
- OCR key-anchor recall: `>=0.95`, with semantic-label cases reported separately.
- Final bundle evidence R@8: `>=0.90`, only after authorization and hydration metrics are visible.
- Citation page precision: `>=0.98` for digital PDF and `>=0.95` for OCR/visual evidence.
