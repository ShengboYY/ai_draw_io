# Material RAG research experiment v1

This experiment measures where the project loses evidence between source ingestion and the final
answer. It is intentionally separate from the release-gate seed dataset: research cases may change
while hypotheses are tested, but every published run pins its corpus, processing profile, retrieval
profile, model and code commit.

## Research questions

1. How much recall is lost at parsing, OCR, chunking, candidate retrieval, authorization, hydration
   and final bundle selection?
2. Which query families benefit from lexical, dense, hybrid RRF, reranking and visual evidence?
3. Which current limits (`40 -> 30 -> 16 -> 8`) remove gold evidence for comparison and multi-hop
   requests?
4. How sensitive are results to OCR quality, language, exact identifiers, document version and owner
   scope?
5. Does disabling Pinecone preserve ordinary text drawing and produce an explicit degraded state?

## Corpus layers

- `controlled`: generated documents with exact page, cell, arrow and version ground truth.
- `challenge`: photographed or degraded images whose ground truth is manually reviewed.
- `open`: pinned public documents downloaded from their authoritative publishers.
- `negative`: documents that deliberately contain nearby concepts but not the requested answer.

The first controlled cohort is generated by `fixtures/generate_fixtures.py`. Generated binaries are
small and source controlled; the script is the authoritative source. The image-generation challenge
fixture is reviewed manually and never used to derive OCR ground truth automatically.

## Evaluation stages

| Stage | Primary metric | Why it matters |
|---|---|---|
| Parse/OCR | character/word error, anchor extraction recall | Separates ingestion loss from retrieval loss |
| Chunk projection | gold-evidence mappability, boundary split rate | Detects facts broken across chunks |
| Lexical candidates | Recall@5/10/40, exact-term Recall@5 | Baseline for IDs, versions and quoted phrases |
| Dense candidates | Recall@5/10/40, MRR@10 | Measures semantic and cross-language retrieval |
| Hybrid fusion | Recall@40, nDCG@10 | Tests RRF weights and duplicate handling |
| Reauthorization | authorized gold recall | Detects scope/version mistakes |
| Hydration | Recall@16, object-read success | Detects timeout and missing-artifact loss |
| Final bundle | evidence Recall@8, facet coverage | Measures actual context delivered to the model |
| Answer/citation | claim support and citation precision | Measures grounded answer quality |

All aggregate recall results must include Wilson or bootstrap 95% confidence intervals and per-slice
counts. A single total score is not accepted.

## Required slices

- English, Simplified Chinese and cross-language query/document pairs.
- Digital PDF, scanned PDF, standalone image, table and visual relationship.
- Exact identifier, paraphrase, comparison, multi-hop, summary and no-answer.
- Automatic source selection, explicit source selection, V1 pinned and latest-version behavior.
- Same owner, wrong owner, same chartbook and out-of-scope chartbook.
- Clean, rotated, blurred, low-contrast and two-column OCR.

## Ablation matrix

Run the same cases with only one change at a time:

1. lexical only;
2. dense only;
3. current weighted RRF (`lexical=1.2`, `dense=1.0`, `k=60`);
4. RRF plus reranker;
5. hybrid plus verified visual evidence;
6. candidate limits 20/40/80, hydration limits 8/16/24, bundle limits 8/12;
7. chunk profiles: current, smaller leaves, larger parent context;
8. OCR selection and confidence thresholds around the current profile.

## Initial implementation hypotheses

These are hypotheses to test, not conclusions:

- Visual-route failures will be dominated by the current explicit `VISUAL_VERIFICATION_REQUIRED`
  stop, not by Pinecone recall.
- Exact identifiers will favor lexical retrieval; paraphrases and cross-language questions will favor
  dense retrieval.
- The final eight-item bundle and three-items-per-material cap may reduce comparison/multi-hop recall
  even when candidate Recall@40 is high.
- Punctuation-only query decomposition may underperform on long Chinese multi-intent questions.
- The fixed `quality >= 0.20` filter may disproportionately remove degraded OCR evidence.
- A learned or cross-encoder reranker should improve Precision@5, because the current online path uses
  RRF but has no semantic reranking stage.

## Safety

Use only synthetic owner aliases and a namespace containing `test` or `dev`. Never place production
documents or user identifiers in this corpus. Every live run must delete its uniquely prefixed vectors
and verify deletion.

## Reproduce the current baseline

Generate the deterministic controlled corpus:

```bash
python3 -m pip install -r evaluation/material-rag-research-v1/requirements.txt
python3 evaluation/material-rag-research-v1/fixtures/generate_fixtures.py
```

Fixture generation currently requires Arial Unicode at `/Library/Fonts/Arial Unicode.ttf` or the
macOS supplemental-font location recorded in the generator.

Render PDFs before accepting fixture changes:

```bash
pdftoppm -png -r 144 \
  evaluation/material-rag-research-v1/fixtures/generated/pdfs/controlled-operations-guide-v1.pdf \
  tmp/material-rag-render/v1
```

The live Java experiment must use the same tokenizer as the Worker profile. Export the pinned
`/worker/tokenizer.json` from the Worker image to an ignored temporary path and set:

```bash
export MATERIAL_RAG_TOKENIZER_PATH="$PWD/tmp/material-rag-tokenizer/tokenizer.json"
export MATERIAL_RAG_OPEN_SOURCE_DIR="$PWD/tmp/material-rag-open-sources"
```

Then load `.env` and run either the controlled or pinned open-PDF method:

```bash
mvn -q -pl ai-agent-draw-io-ingestion-worker -am \
  -Dtest=ControlledPdfDenseRecallLiveTest#shouldMeasureDenseRecallAfterTheRealPdfAndChunkPipeline \
  -Dsurefire.failIfNoSpecifiedTests=false test
```

```bash
mvn -q -pl ai-agent-draw-io-ingestion-worker -am \
  -Dtest=ControlledPdfDenseRecallLiveTest#shouldMeasurePinnedOpenPdfDenseRecall \
  -Dsurefire.failIfNoSpecifiedTests=false test
```

The open-source files must match `sources/manifest.json`. The live tests refuse namespaces whose
names do not contain `test` or `dev`, and clean vectors in `finally`. Large upserts and deletes are
batched to stay within Pinecone request limits.

Evaluate OCR output named `page-1.txt` through `page-3.txt` with:

```bash
python3 evaluation/material-rag-research-v1/analysis/evaluate_ocr.py \
  tmp/material-rag-ocr-results
```

The first measured report is `results/2026-07-20-baseline.md`. It is a diagnostic baseline; its 66
defined cases do not replace the planned 180-case reviewed release suite.
